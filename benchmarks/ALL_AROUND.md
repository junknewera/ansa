# План реализации и приёмки публичного бенчмарка

Цель — сравнить две конфигурации ANSA на одной задаче через обычный Carbon, сохранив исходные данные, журнал, результат и решение независимого оценщика. Перечень задач зафиксирован в [#73](https://github.com/junknewera/ansa/pull/73).

| Этап | Реализация | Критерий приёмки |
| --- | --- | --- |
| 1. Входы и воспроизводимость | Подготовщик выбирает задачи по ID, получает закреплённые версии источников и формирует manifest v1. Стенд фиксирует SHA-256 входов, проверяющих программ и конфигурации MCP. | Команда планирования выводит задачи, расписание и хеши до обращения к модели. |
| 2. Linux, Git, ML/NLP | Воспроизвести состояние файлов InterCode, потерянный коммит в reflog и два задания Terminal-Bench на токены и поиск. Для Git подготовить историю перед фиксацией исходного HEAD. | Эталон проходит, ошибочный результат отклоняется. Для Git проверяются история слияния и файлы. В журнале оценщика InterCode сохраняется численный reward. |
| 3. Диалог и MCP | Передать все реплики BFCL в один сеанс Work. Для декомпиляции подготовить фиксированный объект x86-64 и MCP-инструмент чтения дизассемблированной функции. | BFCL проверяет последовательность ходов и состояние виртуальной ФС. Оценщик декомпиляции требует подтверждённый вызов инструмента и успешный запуск C-тестов. |
| 4. Задачи с изображениями | Подготовить оригиналы изображений CharXiv и SWE-bench Multimodal, привязать каждое к индексу пользовательской реплики и сохранить его хеш. | До появления транспорта в Carbon отчёт сохраняет режим, модель и причину `unsupported`. Такие строки не дают побед в A/B. |
| 5. Парное сравнение | Закрепить одну изменяемую настройку, семейства задач, development и holdout. Проверить оценщик эталоном и контрпримером до старта агентов. | Отчёт показывает исход каждой пары, категории, покрытие, время, вызовы и доступный расход токенов. Для изменений отдельной стадии требуется запись о её выполнении. |
| 6. Приёмка на моделях | Сохранить план, запустить development, затем отдельно holdout на зафиксированной паре. | Опубликовать идентификаторы сборок и манифеста вместе с результатами; отдельно указать ошибки среды и неподдерживаемые сочетания. |

## Как закрыть поддержку изображений

1. Добавить в пользовательский ввод Carbon привязку локального изображения к конкретной реплике. Проверить тип и размер до принятия команды. Владельцем копии становится сессия, чтобы продолжение и replay использовали те же байты.
2. Провести ссылку на содержимое и MIME-тип через команду submit, журнал принятой реплики и построение запроса провайдеру. Проверить чтение существующих текстовых журналов.
3. Добавить тест Carbon через PTY и тестовый транспорт. Проверить байты оригинала и порядок частей в запросе Work, затем повторить для каждого заявленного режима и маршрута.
4. Переключить только подтверждённые сочетания на исполнение и прогнать оба оценщика. Для SWE-bench проверить исходную ревизию Chart.js, воспроизведение падения и прохождение тестов после правки.

Команды подготовки и запуска — в [README](README.md), строгий A/B — в [COMPARISON.md](COMPARISON.md).
