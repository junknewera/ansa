# M1 - JSON, early supervisor и HTTP/TLS risk spikes

Статус: native closeout выполняется. Production `ansa` и Nix default остаются C++20;
Rust executable содержит только private synthetic process modes и отказывает обычным
runtime-командам. M0 baseline и согласованные performance budgets сохранены.

## Результат и границы

Три короткие реализации отвечают на blockers из
[M1](../RUST_MIGRATION_PLAN.md#m1--ранние-рискованные-проверки):

- `protocol/json.rs` владеет значениями, сохраняет numeric lexemes, порядок arrays
  и object dump, декодирует строки и отклоняет повторные decoded keys. Object
  equality, как у C++, не зависит от порядка ключей; numbers сравниваются по
  исходному token. Лимиты: 16 MiB, depth <64, 131072 value nodes.
- `legacy_json_v1.rs` воспроизводит tool/instruction/plan/compact/evidence preimages
  и hashes. C++ adapter использует production Json, ToolRegistry, SessionState и
  compact builder. Evidence preimage повторяет layout приватного C++ process
  codec; это проверка bytes/hash, не двунаправленный recovery/journal из M6-M7.
- Private reexec supervisor запускается до Tokio/auth, проверяет platform
  capabilities и consume-once перед synthetic effect, отменяет primary и
  отделившегося через setsid потомка, затем reap-ит их. HTTP probe на localhost
  сохраняет interim heads, BODY и trailers и возвращает успех только после EOF.

Число `executors:0` у HTTP probe означает отсутствие executor path в spike.
Полный Responses reducer и batch admission относятся к M2. Настоящих provider,
auth, journal, tools, CLI/TUI и runtime owner здесь нет. JSON использует повторный
разбор borrowed RawValue; independent review измерил около 1.11 s против 0.048 s
для C++ в Debug на глубоком 1 MiB input. Это ограниченная correctness-проверка,
не performance parity; перед включением в runtime нужна оценка по budgets M0.

## Процессы

`ansa-linux` содержит narrow libc unsafe только для inherited signal reset и
synthetic seccomp fault; остальные операции используют std/rustix. Перед exec
проверяются single thread, matching non-root UID/eUID, procfs children, subreaper
readback, no_new_privs и обнулённые capabilities. Реальный owned child проверяет
pidfd_open/send_signal и повторный waitid(WNOWAIT). Missing-pidfd case устанавливает
локальный NNP seccomp filter и требует EPERM из pidfd_open штатного probe до
создания consume marker. Отдельный отказ pidfd_send_signal не заявляется.

Owned private directory открывается по компонентам без symlinks. Durable EXCL
consume marker предшествует эффекту, dev/inode binding и отдельные EXCL claims
защищают primary/detached helper от повторного запуска. После intent fsync ещё
раз проверяется Cancel/EOF. Cleanup сигналит через pidfd только waitable owned
или adopted children, удерживает primary wait status до завершения descendants.

11 isolated fault cases включают inherited signals, control EOF, Cancel после
intent, missing procfs/pidfd, повторный dispatch/helper, directory substitution
и смерть supervisor. При смерти supervisor outcome неизвестен, retry блокируется
consume marker; независимый test controller усыновляет и очищает descendants.
Без cgroups не обещается cleanup после смерти самого supervisor. Эти fixture
файлы не являются вторым session journal или production recovery API.

## Выбор transport и ограничения

Сравнены публичный API и исходники pinned reqwest 0.13.5 и выбранного Hyper 1.12.0.
Reqwest позволяет получить body frames/trailers через преобразование Response;
утверждение «reqwest скрывает trailers» неверно. Но его async client пересобирает
Hyper Request без пользовательских extensions, теряя on_informational callback;
публичного HTTP/1 max buffer setter также нет. Поэтому spike использует явный
Hyper connection с owned driver. Это API/source comparison; второго production
HTTP adapter и заявления о performance-сравнении нет.

Первичные исходники: [reqwest client](https://docs.rs/reqwest/0.13.5/src/reqwest/async_impl/client.rs.html),
[reqwest Response](https://docs.rs/reqwest/0.13.5/src/reqwest/async_impl/response.rs.html),
[Hyper informational callback](https://docs.rs/hyper/1.12.0/hyper/ext/fn.on_informational.html).
Cargo.lock фиксирует версии; отключены default features, единственный TLS provider
- rustls/ring, без AWS-LC/native-tls/OpenSSL Rust backend. Tokio current-thread.

HTTP/1 per-head buffer и cumulative allowance ограничены 64 KiB, fields final
head + trailers - 256, interim heads - 256, BODY - 16 MiB. После origin TLS/CONNECT
узкий IO counter ограничивает raw plaintext body_limit + 64 KiB. Успешный H1 EOF
требует `total_wire_bytes - delivered_body_bytes <= 64 KiB`: reason phrases, OWS
и trailers не теряются при нормализации. H2 ограничивает decoded header list
64 KiB, cumulative semantic bytes/fields и body frames. Driver на обычном выходе
abort/join; при внешнем Drop future guard вызывает abort. Полный runtime Cancel
с явным join lifecycle остаётся задачей runtime milestone.

Три сознательных ужесточения reviewed независимо и закреплены exact fixtures:

| Fixture | C++ | Rust | Причина |
|---|---|---|---|
| `http-obsfold` | accept | reject | Hyper отклоняет obsolete folded syntax, которую curl нормализует |
| `http-info-count` | accept | reject | Не более 256 interim heads |
| `http-chunk-budget` | accept 14000 BODY bytes | reject после 14000 bytes | Chunk framing тоже расходует raw allowance 64 KiB |

`http-info-byte-budget` и `http-long-reason` отклоняются обоими adapters: C++ до
BODY, Rust после 26 uncommitted bytes на EOF. Это только диагностический prefix;
accepted history отсутствует. Проверка допускает ровно эти два различия стадии
отказа, остальные неизвестные расхождения закрывают gate.

49 local transport cases проверяют TLS CA/hostname, H1/H2, MIME duplicates/trailers,
неполный transfer, лимиты, redirects, HTTP forward/HTTPS CONNECT/SOCKS4/4a/5/5h,
proxy case precedence и NO_PROXY. Конфигурация proxy synthetic; реальный proxy env
не используется. Local/system DNS для localhost и remote/local SOCKS hostname
проверены по wire observations; произвольные resolver/DoH/PAC конфигурации сюда
не входят. Unsupported proxy не вызывает direct fallback. Gzip bytes сохраняются
без decompression, Accept-Encoding не добавляется. TLS CA и server private key
в fixtures являются публичными synthetic test data и не годятся для реальных
сервисов. H2 reset обязан произойти после доставки всех 26 apparent-terminal bytes.

## Проверки и воспроизведение

```sh
nix develop --no-update-lock-file -c cargo test --manifest-path rust/Cargo.toml --workspace --locked
nix develop --no-update-lock-file -c cargo fmt --manifest-path rust/Cargo.toml --all --check
nix develop --no-update-lock-file -c cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --locked -- -D warnings
nix develop --no-update-lock-file -c cargo build --manifest-path rust/Cargo.toml --examples --bins --locked
nix develop --no-update-lock-file -c python -m unittest discover -s tests/parity -p 'test_*.py'
nix develop --no-update-lock-file -c python tests/parity/run.py compare --suite risk --cpp-build build-m1 --rust-target rust/target --output build-migration/M1
nix develop --no-update-lock-file -c python tests/parity/run.py fault --suite risk --cpp-build build-m1 --rust-target rust/target --output build-migration/M1-fault
nix develop --no-update-lock-file -c python tests/parity/run.py check --milestone M1 --evidence build-migration/M1
```

Compare требует 548 JSON, 5 domain vectors (25 hashes) и 49 transport cases.
Fault требует JSON negatives, те же transport cases, 11 Rust и 8 C++ process suites.
Каждый capture сохраняет source/binary/fixture identities, argv, exit/timeout,
точные stdin/stdout/stderr. Повторное использование каталога запрещено. Ошибка
или timeout adapter сохраняют partial raw outputs до assertions. Checker требует
обе матрицы и повторно проверяет raw JSON, hashes, body/interim/trailers, proxy
observations, case request contract и identity adapters. Agreeing all-reject или
одинаковая потеря BODY/trailers/interims не проходят. Это проверка воспроизводимой
evidence, не защита от намеренной подделки человеком всех файлов и hashes.

Неподдерживаемые future suites и perf остаются nonzero. M1 check отвечает только
за risk captures; полный milestone дополнительно требует C++/Rust/native gates
и independent review. Native closeout и tested SHA будут зафиксированы после
завершения проверок. Следующий milestone - M2, полный protocol/replay/admission.

## Независимое ревью

Три read-only native агента проверили разные границы:

- `m1_json_review`: numeric acceptance, decoded duplicates, uppercase escapes,
  object equality, 548 JSON cases и все 25 hashes. Дополнительно выполнены 3020
  generated numeric checks и focused boundaries; открытых замечаний нет.
- `toolchain_probe_facts`: fresh-exec/signal/pidfd ownership, preflight до consume,
  directory identity и EXCL claims, seccomp BPF/unsafe lifetime/varargs. Исправлены
  fake denial test и диагностическая проверка реального EPERM; signoff получен.
- `m1_transport_review`: header count/bytes, forward против CONNECT, H2 prefix до
  reset, raw failures/timeouts, independent expected BODY/interim/trailers и
  replay input/binary identity. Все findings исправлены и проверены повторно на
  602/286 matrix. Более строгие syntax/interim/chunk limits reviewed явно.

Self-review и `git diff --check` дополняют эти проверки. C++ production sources
не меняются; новый C++ target - только test oracle.
