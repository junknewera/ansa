# M9 - bounded live acceptance и обратимый cutover

Статус: **GO - bounded live acceptance пройдена**, 2026-11-15.
Проверенный clean code checkpoint:
[`742d29c`](https://github.com/junknewera/ansa/commit/742d29cae55cfd993d3ce817962fbabdcccb6a99),
tag `migration/m9-cutover`. Base: merge PR #13 `9e6e6de`.

Пользователь в текущей сессии разрешил продолжить ранее предложенный M9,
если local-harness-benchmark ещё рано использовать. Проверка исходников стенда
подтвердила: подготовлены задачи/evaluator, но runner и adapter ansa отсутствуют.
Изменение benchmark и внешние Codex/Claude прогоны в M9 не входят.

## Согласованная live-граница

- Текущий собственный профиль ansa и неизменные client/account/session binding;
  модель `gpt-6.1-sol`. Реальный store открывает только production executable.
- Всего не более 12 generation/summary requests. Перед каждым из трёх процессов
  с единственным Submit сохраняется невозвратный резерв 4 requests: максимум
  2 tool rounds + final generation и одна возможная pre-Submit compaction.
  Проектная конфигурация проверяется через production `--print-config` до сети.
  Resume, дополнительные Submit и автоматические повторы не выполняются.
  Служебные auth/catalog HTTP-запросы не являются model requests.
- Тестовый каталог `/tmp/ansa-m9-*`: read_file, безопасная foreground-команда,
  durable Done; restart/continue без повторения tools; адресный Cancel команды
  с задержкой, known cancelled outcome, восстановление termios и restart.
- Одна явная `--refresh-auth` и штатное обновление при работе; без logout/login.
  При отсутствии текущей авторизации прогон останавливается.
- C++ fallback открывает самую свежую завершённую сессию без Submit; journal
  bytes должны сохраниться. Credentials/journal backups не откатываются.

## Проверки и выбор пакета

До live повторяется полный offline `compare --suite e2e` на точном clean code SHA.
Production core/providers/tools/session codecs не меняются. Проверяются native
workspace, frontend, locked pins, Nix packages и независимый review.

В ветке подготовлен выбор Rust release candidate по умолчанию: `nix run .#`,
aliases `ansa`/`ansa-rs`. `nix run .#ansa-cpp` сохраняет C++ fallback, а
`.#ansa-rust` остаётся совместимым явным выбором Rust. Глобальная установка и
переключение пользовательского shell не выполняются. Удаление C++ - только M10.
При провале live/default не объявляется GO; PR не выдаётся за принятую миграцию.

Получено **5 успешных responses**: 3 primary, 1 continue, 1 cancel. Ledger до
запуска резервировал 4 на сегмент, всего **12**; резерв не возвращается и новых
live attempts после приёмки не было. Денежная стоимость не измерялась.
Primary занял 17,02 с, continue 5,95 с. Один наблюдённый Cancel: ack 2,98 мс,
все pinned ancestors завершились к 33,63 мс до EOF; Cancel до полного выхода
process/PTY - 56,04 мс. Это одиночные наблюдения, не p95 performance-приёмка.

Reasoning items провайдер не прислал: encrypted reasoning отмечен **not_observed**.
Фактический replay проверен для присланных native items/results, binding и epoch;
synthetic opaque-reasoning coverage M8 не выдается за live-наблюдение.

Rust ELF **6,30 MiB**, closure **63,44 MiB**. Production `.rs`, C++ sources,
Cargo.lock, зависимости и toolchain pins относительно base не менялись.
Полная performance/fault-матрица M8 не переснималась. C++ Debug/ASan/UBSan gates
переиспользованы из сохранённого M8: native inputs неизменны, установленный
C++ Release побайтово совпадает с M8:
`420c80f7e7b9787e1b6eba18097f0ec97d3b25cc11630b4b0f1a840f88206ff0`.
X86_64 packaging только evaluated, native execution остаётся aarch64.

## Исправления стенда и reviews

Первый compare остановился до cases из-за Cargo hardlinks; собственные build
executables отделены без изменения bytes. Второй compare обнаружил недостающие
скопированные C++ native test binaries; полный третий capture прошёл. Оба
неуспешных attempt сохранены. Production/runtime bugs этими отказами не выявлены.

Pre-live review усилил стенд: profile проверяется перед каждым Submit; полный
Request связан с accepted.next и native continuation; проверяются account hash,
порядок transitions, operation_run/revision, known outcomes, реальные PTY reopen
и process ancestry/cleanup до вмешательства harness. Negative controls отвергают
подмену контекста/account/operation, потерю reasoning, один batch вместо раундов,
изменённый config, no-op fallback и неизвестный cleanup.

Packaging review также выявил устаревшее предположение perf-checker, что default
всегда C++. Он теперь выбирает explicit ansa-cpp на pinned revision и использует
legacy default только при отсутствии этого атрибута. Ошибки explicit fallback
не скрываются; numeric resource budgets не менялись.

Два независимых review-агента проверили packaging и весь offline raw corpus,
а затем 34 retained live artifacts. Они не повторяли live calls и не открывали
real auth/session stores; проверялись только скопированные acceptance journals.
