## Реализовано

- OMHJ1 reader/writer с прежними part/envelope/frame bytes, sequence,
  complement, SHA-256 и связью parts. Оборванный хвост сохраняется; новая part
  ссылается на hash всех исходных bytes. Unsupported/corrupt state остаётся
  read-only и не исправляется overwrite.
- Transactional reducer всех 11 событий: init, accepted, response, intent,
  outcome, continued, compacted, done, cancel, pause, resume. IDs, mode,
  provider/account/model, limits, known/unknown effects и batch prefix сохраняются.
- Exact context epochs, legacy native compaction и summary с неизменным хвостом
  двух turns. Saved response загружается через production M2 admission;
  второго semantic validator и Deserialize обхода private admission нет.
- Persistent transcript blocks с owning immutable snapshots, cursor pages,
  максимумом 64 entries и 256 KiB. Explicit catalog создаёт и выбирает private
  session metadata с проверкой cwd/profile/id, без discovery пользовательских stores.
- Store валидирует candidate, пишет и fsync-ит record, затем публикует новое
  состояние. Failed outcome сохраняется отдельно как известный результат;
  failed done не публикует assistant. Worker владеет journal, имеет очередь
  capacity 1, bounded reply и явный drain/join.
- Recovery может принять проверенное evidence от tool reader и записать outcome
  один раз. Она не вызывает executor. После restart нужен explicit Resume;
  unresolved intent остаётся unknown и не повторяется автоматически.

Использованы существующие crates, JSON/request/response codecs и raw-command
helpers. Cargo.lock не изменён: 146 external packages, новых dependencies нет.
Все файлы сессий, tool outputs и identities синтетические; пользовательские
сессии и credentials не открывались.

## Проверенные сценарии

Actual C++ `.log` fixtures покрывают 16 traces: completed, paused, cancelled,
old missing mode, plan, outstanding intent, known prefix, resumed/not-started,
effect_unknown, summary/native compact, two-call batch и multi-round. Failed-known
prefix проходит pause/reopen/resume и следующий intent/continuation, сохраняя
operation IDs и output. Оба направления write/read проверены на каждом trace;
дописывание другим binary и обратное reopen не меняют исходные bytes.

373 pure cases проверяют codecs, каждый prefix traces, missing fields, wrong
stage/identity, result execution/effects/dispatched matrix, summary negatives и
граничный positive 16384 bytes. Request/response/result/summary/compact имеют
независимые полные expected values. JSON booleans, number lexemes и native arrays
сравниваются точно; только diagnostic конкретного rejected step может отличаться.
Context/native поля с именем diagnostic сохраняются в сравнении.

Fault содержит **320 byte cuts** representative frame, включая все part/frame
header и body boundaries; clean header на 92 bytes служит positive control.
Проверены 12 malformed/unsupported states, 8 link/FIFO guards с реальными
retained sentinel bytes и shared lock между независимыми C++/Rust processes.
Все 11 event kinds проверены на before/after write и sync: **88 crash cases**
с exit 71 и recovery другим binary. Observer IO cases отдельно проверяют
отсутствие undurable assistant.

**22 actual syscall cases** используют test-only LD_PRELOAD DSO только для
explicit marked `/tmp/ansa-m4-*/journal`. Подменяются write/fsync: short/zero/
partial write, ENOSPC/EIO/EINTR, header/file/directory sync и outcome/done sync.
Каждый случай обязан сохранить проверяемый raw fault-fired marker; простая
декларация об инъекции не проходит. Interrupted/short operations завершаются
корректно; неясные записи сохраняются и не получают ложного acknowledgement.

Дополнительный archived script проверяет valid prefix перед torn record,
следующую torn part header и последующие Rust/C++ appends в третью part.
Ожидаемые события - 1, 3, 4; обе исходные parts побайтно неизменны.

## Исправления и review

- Expected size фиксируется до scan; обнаруженный рост файла не принимается
  за уже восстановленный state. Перед append проверяются inode/name/size.
  Общий flock и conflict checks не обещают atomic CAS против uncooperative writer.
- C++ и Rust отклоняют hardlinked lock/parts. C++ получил NONBLOCK против FIFO
  и NUL path guard. Некорректное UTF-8 part name даёт read-only diagnostic.
- Adapter marker проверяется до read; JSONL bounded при чтении. Бинарники/DSO
  читаются с canonical path, NOFOLLOW/NONBLOCK, regular/executable/size/link
  guards. Для M4 сохранена отдельная single-link копия Cargo example.
- Checker сохраняет NumberToken и exact dump, не удаляет diagnostic рекурсивно,
  проверяет actual raw sentinel/marker bytes и полные codec values. Boolean
  exit, timeout, missing cases и подменённые argv/stdin/raw hashes не проходят.
- Перенесены C++ transcript assertions: 300 entries, snapshot 64 до cancel,
  cross-block/oldest pages и 24 sized entries с 256 KiB limit. Добавлены wrong
  summary request, empty/refusal/16385 negatives и failed-known reducer trace.

`my-code-reviewer` проверил reducer/codec/epoch/transcript/catalog и закрыл
coverage findings. `security-auditor` проверил journal/worker/IO/adapters/checker,
самостоятельно повторил final checker, сверил **110 compare commands**, **1678
fault commands**, все 22 syscall markers и отверг 8 targeted tamper mutations.
Финальные signoffs сохранены в baseline `review.md`.

## Воспроизведение и сохранение

В pinned `nix develop --no-update-lock-file`, после сборки C++ targets и всех
Rust examples/bins с all features:

```sh
cargo test --manifest-path rust/Cargo.toml --workspace --locked
cargo fmt --manifest-path rust/Cargo.toml --all --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings
ANSA_PARITY_CPP_BUILD=build-m4 python -m unittest discover -s tests/parity -p 'test_*.py'
python tests/parity/run.py compare --suite sessions --cpp-build CPP_BUILD --rust-target SINGLE_LINK_RUST_TARGET --output FRESH_COMPARE
python tests/parity/run.py fault --suite sessions --cpp-build CPP_BUILD --rust-target SINGLE_LINK_RUST_TARGET --output FRESH_FAULT
python tests/parity/run.py check --milestone M4 --evidence FRESH_COMPARE --fault-evidence FRESH_FAULT
nix build --no-update-lock-file .#ansa-rust
```

CPP_BUILD содержит `ansa_session_oracle` и `libansa_journal_fault.so`.
SINGLE_LINK_RUST_TARGET/debug/examples/session_adapter - обычная копия built Cargo
example, без hardlinks. Capture требует новый output directory. Final captures
выполнены из отдельного clean checkout с проверенными build outputs.

Baseline - `~/Workspace/pet/ansa-baselines/m4-453ba6f/`: raw final/failed attempts,
точные scripts/logs/source/binary/fixture hashes, Git bundles и два indirect Nix
GC roots. C++ Release - `qyvbl5sp...-ansa-0.1.0`, Rust -
`964i98mv...-ansa-rust-0.1.0`; M3 fallback остаётся отдельно.

Два отказа до final gate сохранены: Nix copied read-only fixture запрещала RDWR
до chmod fresh copy; checker ошибочно требовал session-policy отказ от generic
framing Journal. Исправлены test setup и проверяемая API boundary. Первый syscall
smoke не инжектировал fault из-за Nix TMPDIR и был отклонён обязательным marker;
scope и оба adapter guards согласованы на fixed /tmp. Failed evidence не менялось.

## Границы

Journal/session port не является Rust runtime. Owner loop, model/tool execution,
runtime cancellation, UI, live/cutover и performance parity остаются следующими
этапами. Формат v1 и fsync ordering сохранены; batching не добавлен.
Следующая отдельная задача - M5: owned runtime, cancellation и summary loop.
Автоматически не начинать.
