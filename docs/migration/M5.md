## Реализация и границы

Один Tokio current-thread owner управляет session state. Journal, provider,
tools и authorization выполняются четырьмя отдельными owned workers с bounded
очередями. Их handles сохраняются до join. Блокирующий callback не занимает
journal worker или control owner; shutdown ожидает завершения уже начатой работы.

Весь batch проходит admission до первого executor. Порядок dispatch:
authorization, durable intent, authorization/lease recheck, executor, durable
outcome, следующий tool. Закрытый consume-once receipt связывает identity и
invocation с подтверждённым storage completion. Публичный старый batch API
отклоняет durable tools без checkpoint; безопасный batch смешанного registry
остаётся доступен.

Cancel имеет отдельный bounded mailbox. Incarnation, turn, request, resume epoch
и generation проверяются перед dispatch и при completion. Known late outcome
сохраняется после отмены и при ошибке записи; unknown блокирует автоматический
повтор. Незапущенный intent закрывается как not_started. Restart ожидает явного
Resume и сохраняет выполненный prefix.

CLI/TUI получают общие owning typed commands/events, bounded outbox,
snapshot/resync и latest preview. Summary использует production admission и
M4 codec, сохраняет exact recent tail и меняет epoch после durable acknowledgement.
Реальные file/AGENTS tools и auth persistence подключаются позднее; блокирующий
I/O в M5 проверяется injected tool/auth callbacks и journal barriers.

outcome/continued/done и 20 дополнительных stress schedules. Native tests

по три executors. Отклонённый первый capture сохранён отдельно.

## Provenance, review и fallback

Полная C++ matrix выполнена один раз. Nix C++ собран из `0888c66`; все **65**
native C++/CMake/flake inputs совпадают с финальным checkpoint. После этого
менялись Rust owner и его tests/harness. `cpp-source-proof.json` сохраняет hashes.
Release executable имеет тот же SHA-256, что M4 fallback:
`420c80f7e7b9787e1b6eba18097f0ec97d3b25cc11630b4b0f1a840f88206ff0`.

M1-M4 adapters собраны на `0888c66`; их captures/checkers сняты повторно из clean
`2eb480b`. Из **60** Rust production/config inputs изменился только M5 owner,
который эти adapters не вызывают; остальные **59** совпадают. Proof сохранён в
`regression-source-proof.json`. M5 runtime adapter пересобран после race fix;
финальный Nix Rust build и весь его workspace относятся к `2eb480b`.

Два независимых native review завершены без открытых findings. Проверены
worker/lease/receipt ownership, shutdown, cancellation, stale identity, summary,
admission и evidence checker. Security reviewer повторил M5 raw checker:
66 compare и 114 fault PASS; второй reviewer повторил 17 checker regressions.
Обнаруженные API bypass, queue acknowledgement, cleanup panic, startup limits,
preview starvation, shutdown race и false-PASS paths исправлены с регрессиями.

Evidence, failed/superseded attempts, binaries, source bundle, hashes и GC-rooted
Nix outputs сохранены в `~/Workspace/pet/ansa-baselines/m5-2eb480b/`.
Рабочий capture checkout: `/tmp/ansa-m5-runtime-owner`.

Не проверены physical power loss, x86_64, ThreadSanitizer и длительные live
сессии. Cancel не отменяет совершённый эффект; fsync и некооперативный callback
не имеют обещанного bounded cleanup. M5 не даёт разрешения на live pilot или
удаление C++.
