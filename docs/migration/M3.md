## Реализовано

- Explicit RS256/JWKS signature и issuer/audience/azp/nonce/time policy,
  discovery, own dynamic client registration, host UUID, PKCE, bounded loopback
  callback с exact state/path и единственным Host.
- Совместимые `registration.json`/`credentials.json` v1: identity/account hash,
  client/host/session/nonce/scope/time сохраняются при чтении и refresh.
  C++ читает Rust writes, Rust читает C++ writes. Refresh сохраняет session;
  повторный login создаёт новую session.
- Private directory/file guards, bounded reads, общий flock, stop-aware ожидание,
  atomic replace и file/directory fsync. Durable exchange/refresh pending
  фиксируется до injected POST. Неясный refresh не повторяется автоматически.
- Signed-out marker пишется до ожидания execution lease; active lease получает
  cancel. Watcher владеет нужными ресурсами и завершается с join, в том числе
  после удаления manager. Revocation uncertainty остаётся sticky.
- Локальные status и создание dispatch guard не вызывают network. Access/models
  нужны при dispatch. Authorized generation использует production M2 validator.
  Секреты скрыты в Debug и не попадают в обычные diagnostics.

Все fixtures, keys, account IDs и exchanges синтетические. Existing credential
stores и реальные login/refresh/logout не использовались. Реализацию завершил
основной агент; два отдельных native агента выполнили независимое ревью.

## Corpus и независимые assertions

Все 16 C++ auth suites перенесены с проверками поведения и parameterized loops,
а не пустыми registration names. Pure corpus проверяет signed JWT mutations,
claims, malformed JSON/base64, discovery, PKCE/forms и callback. Генератор C++
не является единственным oracle: Python независимо проверяет RSA PKCS#1 v1.5
signature и точные signed bytes перед мутацией, затем ожидаемые claims/account
hash. Совпадающее ошибочное значение или all-reject не дают PASS.

Два interop cases выполняют по 13 действий с обоими binaries на одном store:
login, reopen/status, refresh в обе стороны, access, logout, denied access,
reauth и failed/repeated revocation. Проверяются точные bytes read-only шагов,
binding, смена refresh token и сохранение session.

Fault включает **21 точку падения** для каждого writer, обязательный exit 71,
snapshot до восстановления и recovery другим binary. Покрыты synced temporary,
pending/replacement/dispatch, удаление tokens и durable logout marker. Неясный
POST не повторяется; известная полная replacement остаётся доступной.
Также проверены **29 file/store guards** для обоих adapters, неизменность
принадлежащих тесту sentinels и настоящий одновременный C++/Rust refresh:
ровно один POST. Oversized/unterminated JSONL отклоняется до операций.

Raw stdin/stdout/stderr, argv/cwd/exit/timeout, snapshots и source/binary/fixture
hashes сохранены. Checker отвергает missing/skipped/reordered cases,
подменённые raw bytes, metadata и платформу; diagnostics сверяются со static
codes. Проверки не требуют доступа к произвольным каталогам пользователя.

## Явные stricter corrections

Пять отличий разрешены точными case IDs в manifest, с positive controls и
независимым review:

- `jwt-exponent-34-bits` и `jwt-exponent-64-bits`: ring требует exponent не
  больше 33 bits. C++ принимает эти корректно подписанные synthetic fixtures,
  Rust отклоняет до claims admission.
- `jwt-leading-zero-modulus` и `jwt-leading-zero-exponent`: Rust требует
  canonical unsigned components без ведущего нуля; C++ принимает их.
- `store-ancestor-symlink`: Rust проходит каждый компонент через directory FD
  с NOFOLLOW. C++ допускает ancestor alias. Тест использует только fresh private
  fixture root и проверяет ноль POST; обычный real-path store совместим.

Actual modulus проверяется по bits, а не округлённой длине: 2040/2041/2047
отклоняются, 2048 принимается. Четыре RSA deviations подкреплены валидной
signature; их нельзя объяснить общим отказом crypto fixture.

## Исправления по ревью

- Rust dispatch прекращает поиск после первой подходящей модели, как C++
  `any_of`; malformed catalog tail после неё не меняет результат.
- Test log пишется через descriptor-relative NOFOLLOW/NONBLOCK с проверкой
  owner/mode/nlink/type/size. JSONL ограничен во время чтения; partial EOF
  отвергается. Оба adapters отклоняют NUL root до filesystem calls.
- C++ production callback использует общий строгий validator вместо поиска
  подстроки Host; duplicate Host и DEL отклоняются. Добавлены native regressions.
- C++ reads и logout marker используют NONBLOCK: FIFO не блокирует процесс до
  fstat. NUL запрещён в production auth directory. Эти изменения прошли весь
  Debug/Release/sanitizer gate.
- Total C++ PKCE digest helper поддерживается и для коротких/длинных synthetic
  strings; login использует корректный verifier. OAuth helper не паникует на
  boundary fixtures. Logout observation происходит после file и directory fsync.

`my-code-reviewer` проверил ownership/state/dispatch и crash cases;
`security-auditor` - crypto/store/adapters и independent raw checker. Второй
ревьюер самостоятельно повторил clean M3 checker и сверил 29 compare commands,
298 fault commands и exact source HEAD. Финальные signoffs - в `review.md`
сохранённого baseline.

## Зависимости

Прямые additions: oauth2 5 с `default-features=false`, base64 0.23 и chrono 0.4
со std для точного timestamp поведения C++. OAuth2 используется как узкий PKCE
helper. Cargo.lock: **146 external packages, +67** к M2; прежние versions,
sources и checksums сохранены. Feature graph изменился из-за новых dependencies.
Reqwest/ureq/curl/native-tls/OpenSSL/aws-lc не добавлены; HTTP/TLS остаётся
выбранным transport с rustls/ring. Полный audit и cargo feature tree сохранены.

## Воспроизведение и сохранение

В pinned `nix develop --no-update-lock-file`, после сборки native targets и
Rust examples/bins:

```sh
cargo build --manifest-path rust/Cargo.toml --workspace --examples --bins --locked --features protocol-test-adapter,auth-test-adapter
cargo test --manifest-path rust/Cargo.toml --workspace --locked
cargo fmt --manifest-path rust/Cargo.toml --all --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings
ANSA_PARITY_CPP_BUILD=build-m3 python -m unittest discover -s tests/parity -p 'test_*.py'
python tests/parity/run.py compare --suite auth --cpp-build build-m3 --rust-target rust/target --output build-migration/M3-final
python tests/parity/run.py fault --suite auth --cpp-build build-m3 --rust-target rust/target --output build-migration/M3-final-fault
python tests/parity/run.py check --milestone M3 --evidence build-migration/M3-final
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 python tests/parity/run.py compare --suite auth --cpp-build build-m3-sanitize --rust-target rust/target --output build-migration/M3-sanitized
python tests/parity/run.py check --milestone M3 --evidence build-migration/M3-sanitized --fault-evidence build-migration/M3-final-fault
nix build --no-update-lock-file .#default .#ansa-rust -L
```

Capture требует новых output directories. Все логи, raw final и pilot/failed
attempts, binaries, fixture/source hashes, Git bundle, reviews и indirect Nix
GC roots сохранены в `~/Workspace/pet/ansa-baselines/m3-0ba175f/`.
Сохранены оба Release outputs: C++ `i5qm25n...-ansa-0.1.0`, Rust
`jakfqay2...-ansa-rust-0.1.0`. Прежний M2 fallback остаётся отдельно.

Первый полный harness запуск выявил отсутствующие build-m2 paths в новом
worktree; tests принимают явный build directory, после сборки всех adapters
51/51 PASS. Первый sanitized checker стартовал до появления final fault bundle
и отказал; повторный checker на завершённом bundle PASS. Устаревшие pilots после
изменения source hashes закономерно не считаются final evidence.

## Границы

Это synthetic/offline auth port. Реальный agent bootstrap, live verification,
journal/session writer, owner loop, UI, multi-profile и cutover сюда не входят.
Performance parity не заявляется, JSON optimization отложена по решению
пользователя. Следующая отдельная задача - M4: journal/session v1 и recovery;
автоматически не начинать.
