# Отложенные возможности ansa

Задачи интерфейса и следующие этапы разработки.

- [x] Оформление Carbon: сдержанные акцентные темы, `/theme`, свои палитры,
  просторная компоновка по макету и точные inline diff отдельных правок.
  Результаты и проверенный checkpoint - в [PROJECT_STATE](PROJECT_STATE.md).
- [ ] Палитра из изображения как в DankMaterialShell: выбор обоев/source color,
  алгоритмы Matugen (Expressive, Tonal Spot и другие), contrast и предпросмотр.
  Auto DMS читает готовую системную палитру. Генерация остаётся отдельным
  этапом с ограниченным lifecycle локального Matugen.

- [x] UX: исправить неработающую клавишу `g` при чтении диалога. Сообщено
  пользователем со скриншотом: чат субагента, `HISTORY · follow paused`, после
  Ctrl+C (`отменено`). Проверить переход к началу истории, бинды `g/G` и фокус
  чата; сохранить черновик и добавить PTY-регрессию. В новом согласованном
  управлении чат прокручивается мышью, а g/G применяются в файловой панели.
- [x] UX: устранить мигание левой области чата при прокрутке в Vim
  (сообщение пользователя). На скриншоте - чат субагента слева и файловый
  inspector Source справа. Проверить прокрутку в `$EDITOR` и после возврата
  в просмотрщик: область чата должна оставаться стабильной. Добавить
  PTY-регрессию на перерисовку при прокрутке файла.
- [x] UX: вычитать тексты репозитория: интерфейс, README и документацию через `humanizer-ru`,
  `humanizer` для английского текста и `stop-slop`. Писать прямо о действии
  и результате. Убрать шаблонные противопоставления «не А, а Б» и непрошеные
  пояснения о неподразумеваемых альтернативах. Объяснять ограничения,
  которые влияют на запрос пользователя.
- [x] UX: улучшить оформление вызовов инструментов по примеру Codex на
  скриншоте пользователя. Группировать чтение и поиск, показывать файл или
  команду и понятный статус. Обновлять статус вызова в одной записи,
  раскрывать аргументы, вывод и ошибки по нажатию или клавише. Технические
  метки `prepared` и `Succeeded KnownResult` перенести в детали; сократить
  пустые строки. Добавить проверки компактного вида и раскрытия подробностей.
- [x] UX: доработать Markdown Preview. Во вкладке Preview файла
  `docs/PROJECT_STATE.md` пользователь видит сырые Markdown-ссылки и текст
  без оформления, как на присланном скриншоте.
  Форматировать заголовки, выделение, списки и блоки кода; отображать названия
  ссылок и переносить длинные строки. Добавить PTY-проверку Source/Preview.
- [x] P1: исправить SIWC Responses streaming в Rust. Отсутствующий
  `Content-Type` теперь допускается только для HTTP 200 на проверенном Responses
  POST с `stream=true/store=false`, как в C++ fallback. Strict, duplicate/wrong
  MIME и MIME trailers остаются запрещены. Local HTTP/1.1 и HTTP/2 регрессии
  проверяют успешный ответ и ноль executors при отказах, неполном EOF и timeout
  после terminal body. Повторный запрос к реальному аккаунту остаётся частью
  отдельной live-приёмки; фактические headers пользовательского сбоя не снимались.
- [x] P1: показывать причину паузы и сетевых отказов. Diagnostic сохраняется при
  restart/resync, виден в CLI, `/status` и при отклонении нового Submit. Показаны
  доступность Resume/Cancel; стадия и прошедшее время доступны только по `/status`.
  Отдельная строка ожидания и пояснения HTTP-таймаута убраны. Стадия берётся
  из runtime, отдельные DNS/headers/first-token стадии не определяются.
  PTY проверяет connect/transfer/timeout/MIME в обоих режимах, restart без
  повторного dispatch и восстановление терминала. Storage failure и
  `effect_unknown` сохраняют приоритет; автоматических повторов нет.
- [x] UX: проанализировать актуальные команды и сочетания клавиш Codex и OpenCode,
  составить матрицу «есть в ansa / нужно добавить / не подходит» и реализовать
  выбранные возможности. Первый приоритет - ↑/↓ для предыдущих/следующих
  пользовательских сообщений с сохранением текущего черновика. Также разобрать
  редактирование строки, многострочный ввод/paste, slash-команды,
  подсказки и помощь. История должна опираться на canonical journal.
  Приёмка - реальные PTY, UTF-8, возврат к черновику, busy/rejected Submit,
  Cancel и перезапуск сессии. Поиск слов исключён по решению пользователя.
- [x] UX: добавить `/model` и `/thinking` для выбора модели и уровня рассуждения.
  Выбранные значения сохраняются в сессии и восстанавливаются при продолжении
  и перезапуске; изменения применяются к следующим запросам, с сохранением
  корректных model binding и context epoch.
- [x] UX: добавить `/btw` для отдельного побочного разговора во время основной
  задачи. Он не прерывает основную работу и не меняет её контекст неявно.
- [x] UX: добавить `/fork` для создания независимой ветки разговора из текущей
  точки с сохранением доступной на этой точке истории. Последующие сообщения
  и изменения в ветках не смешиваются.
- [x] UX/runtime: принимать новое сообщение пользователя во время работы агента
  и передавать его на ближайшей безопасной границе: после текущего шага модели
  или завершения уже запущенного инструмента/скрипта. Сразу после этого агент
  учитывает сообщение и обновляет ход работы, не ожидая окончания всей задачи.
  Сообщения не теряются и не дублируются; их очередь и состояние доставки видны.
  Такое уточнение задачи отделить от явного Cancel; адресная отмена остаётся
  доступной, а выполненные эффекты и результаты инструментов сохраняются.
- [x] UX: раскрывать диалог на всю доступную область терминала для чтения и
  копирования. Длинные сообщения и весь диалог должны удобно выделяться и
  копироваться; новые события не сбивают позицию чтения и выделение текста.
  Черновик, курсор ввода и место в истории сохраняются при раскрытии, сворачивании,
  resize и streaming. Поведение прокрутки и копирования согласовать на макете.
- [x] UX: компактно показывать время выполнения задачи от отправки промпта,
  включая все раунды модели и инструментов. Показывать текущий шаг: ожидание
  ответа модели, получение ответа, выполнение инструмента, сохранение, пауза
  или завершение; использовать реальные runtime/provider events и доступные
  progress-сообщения модели. Таймер задачи отделён от технических HTTP-лимитов;
  служебную строку про 75 секунд и её пояснения не возвращать.
- [x] UX: сделать вызовы инструментов прозрачными. Показывать число вызовов,
  имя и назначение текущего инструмента, безопасно отображаемые аргументы/цель,
  состояние, длительность, результат или ошибку. Подробности аргументов и вывода
  раскрываются по запросу; краткий статус остаётся виден во время выполнения.
  Preview должен визуально отличаться от подтверждённого результата, а
  незавершённый preview и `effect_unknown` сохранять явное обозначение.
- [x] TUI: отдельный frontend поверх общего typed runtime API и canonical
  session journal, с той же историей, что у Carbon CLI. До реализации согласовать
  макет, управление, копирование и способ включения (`--tui` или режим CLI);
  вопрос режима по умолчанию оставить для этого обсуждения. Порядок работы:
  макет, общая frontend-модель без изменения поведения, ввод и прокрутка,
  TUI, затем приёмка. Cancel остаётся адресным и доступным под нагрузкой.
  Согласованный результат - Carbon workspace по умолчанию, без отдельного `--tui`.
- [x] PTY-приёмка Carbon/TUI: resize во время streaming и ввода; кириллица,
  wide characters, emoji и большие вставки; медленный/заблокированный stdout
  с доступной отменой; переполнение событий и snapshot/resync без дублей;
  Ctrl+C, EOF, suspend/resume и восстановление termios после штатного выхода
  и обрабатываемых ошибок; crash/restart, незавершённый preview и `effect_unknown`;
  escape-последовательности в ответах и tool output. Сохранить one-shot,
  pipeline, JSONL и NO_COLOR. Отдельно проверить копирование длинного диалога,
  сохранность черновика и позиции чтения при обновлениях.
- [x] Приёмка frontend-изменений: полный locked Cargo, adversarial/PTY и pinned
  ASan на NixOS/aarch64, обязательный Rust-only inventory из M10,
  проверенный checkpoint, зафиксированные ограничения и независимый review.
  CTest относится к сохранённому C++ checkout; Rust UBSan не поддерживается
  pinned toolchain и не считается PASS.
- MCP: подключение серверов, их поиск и запуск для задачи, управление lifecycle, изменение tool snapshots в сессии и корректный replay. Примеры будущих задач - управление приложениями и играми через подходящий MCP.
- Внешние hooks. Политика удаления и перенос в TRASH должны подключаться пользовательским hook вне проекта; встроенного trash-правила сейчас не добавляем.
- Режим Ask как альтернатива full access.
- Интерактивный sudo через отдельный пользовательский канал; пароль не попадает в модель, journal или логи. В текущем этапе повышение привилегий запрещено.
- Orchestrate: координатор и дочерние агенты, распределение задач, bounded lifecycle и отмена, владение файлами, события состояний, сбор и проверка результатов. После реализации становится третьим режимом в переключателе Tab рядом с basic/plan. Визуальная основа остаётся Carbon; сведения об агентах раскрываются в области диалога.
- Token-aware context budget и проверка качества compact на длинных задачах.

Другие открытые технические ограничения и результаты предыдущих milestones - в [PROJECT_STATE.md](PROJECT_STATE.md).

## Согласованный Carbon UX

Эталон - `designs/final-design/`, с исправлениями файлового Preview из PNG `-3`.
Новый интерфейс заменяет обычный интерактивный Carbon по умолчанию; one-shot,
pipeline, JSONL и NO_COLOR сохраняются. Согласованный этап реализован;
результаты и checkpoint - в [PROJECT_STATE](PROJECT_STATE.md).

- Основной экран: чат, закреплённый ввод, реальные этапы и время задачи.
  Inspector открывается по необходимости; на узком терминале расположен под чатом.
  Диалог прокручивается мышью. Печать и отправка сохраняют позицию чтения.
  Esc возвращает последние сообщения, следующий Esc в дочернем чате - родителя;
  в файлах Esc возвращает чат, в меню - закрывает без применения. Выделение текста автоматически копируется при отпускании
  кнопки мыши; обновления не сдвигают выделяемый текст.
- Новое сообщение во время reasoning или tool сохраняется и передаётся модели
  сразу после текущего шага, до следующего действия, без ожидания окончания всей
  задачи. `Ctrl+C` прерывает текущий шаг и ускоряет доставку ожидающего сообщения;
  без ожидающих сообщений останавливает работу. Известные результаты сохраняются,
  storage failure и неизвестные эффекты по-прежнему запрещают новый dispatch.
- `/model` открывает кэш каталога и обновляет его в фоне. Выбор модели открывает
  effort; Enter применяет пару, Esc возвращает список моделей. `/effort`
  (`/thinking` - алиас) меняет уровень отдельно. Выбор сохраняется в сессии.
- `/` в начале любого слова открывает подсказки над вводом. Стрелки выбирают,
  Enter или → вставляет команду. `?` в пустой строке открывает помощь:
  одна команда с описанием в строке. Внутри сообщения команды остаются текстом.
- Фон берётся из терминала; тема задаёт акценты и цвета текста. Таймер,
  этап и анимация работы расположены в диалоге. `ANSA_NO_ANIMATION=1` отключает
  анимацию. Ожидающее уточнение выделяется приглушённым маркером.
- Подробности инструментов показывают аргументы и текст результата с переносами.
  Полный вывод открывается в той же боковой панели; Esc возвращает прежний вид.
- `/agents` показывает дерево помощников текущего main/fork с названиями задач,
  включая завершённых и запущенных через `/btw`. `/sessions` показывает основные
  разговоры и ветки по заголовку и фрагменту, без технических ID в списке.
- `/btw` - отдельный побочный разговор с подтверждённым контекстом и read-only
  tools; передача результата основной задаче только явным действием.
  `/fork` - отдельная независимая сессия с тем же контекстом и рабочей папкой.
- Реальные субагенты разрешены по прямой просьбе пользователя либо явному
  указанию применяемого скилла. Самостоятельный выбор режима не является
  разрешением делегировать. Свои чаты, возврат к родителю и передача результата.
- Read-only Source, Diff относительно Git HEAD и Markdown Preview. Внешний
  `$EDITOR` открывается только при остановленном/завершённом агенте.
  `q` в `/files` открывает одну сохраняемую сессию shell в той же панели.
  В zsh Esc из приглашения возвращает файлы в текущем каталоге shell; в Vim
  сначала `:q`, затем Esc. Ctrl+C относится к программе терминала.
  `/run` убран. Ручные команды и их вывод не добавляются в контекст агента.
- Поиск слов по истории исключён по решению пользователя. История сообщений,
  прокрутка и выбор сохранённых сессий остаются. Бинд `Ctrl+F` и подсказки
  `PgUp`/`PgDn`, `Ctrl+F`, `↑`/`↓` удаляются; сами клавиши навигации остаются.

## Следующий этап субагентов

- [ ] Учесть предел родительского ввода 16 KiB вместе с подписью результата: формат
  handoff, большой ответ в дочерней сессии и явный отказ без повторных попыток.
- [ ] Доработать промпты, разрешения и владение задачами/файлами субагентов,
  включая явное, проверяемое разрешение делегации из применяемого скилла.
  В первой версии запуск доступен через прямую команду `/agent задача`.
- [ ] Конечный ответ субагента - только provider-enforced constrained decoding
  по согласованной схеме. Проверить поддержку текущим SIWC backend, admission,
  replay и ошибки/отказ модели. Prompt «верни JSON» и валидация после генерации
  не заменяют constrained decoding. Пользователь отдельно перенёс этот пункт
  на следующий этап; текущую версию не объявлять соответствующей этому требованию.

## Выбранные команды и ввод

Матрица проверена по первичным документам 2026-11-15:
[Codex CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli),
[код keymap Codex](https://github.com/openai/codex/blob/main/codex-rs/tui/src/keymap.rs),
[OpenCode TUI](https://opencode.ai/docs/cli/tui/) и
[OpenCode keybinds](https://opencode.ai/docs/cli/keybinds/).
Это источники для сравнения, а согласованное поведение ANSA определяет раздел выше.

| Возможность | Codex / OpenCode | Выбор ANSA |
|---|---|---|
| Предыдущий ввод | Стрелки истории | Существующий recall и возврат черновика сохраняются |
| Многострочный ввод | Терминальные сочетания, Ctrl+J | Ctrl+J и распознаваемый Shift+Enter; paste не отправляет текст |
| Сообщение во время работы | Enter уточняет текущую работу | Доставка после текущего model/tool шага |
| Отложенный turn | Отдельное сочетание очереди | Legacy JSONL Submit сохраняется; обычный Enter означает уточнение |
| Выбор модели | Меню модели | /model, /effort, /thinking; только подтверждённые capabilities |
| Побочный вопрос | /btw в OpenCode | Отдельный read-only разговор; явная передача результата |
| Сессии | Выбор сохранённых бесед | /sessions и независимый /fork |
| Локальная команда | Shell mode | q в /files открывает одну сессию shell в боковой панели |
| Копирование | Copy/transcript actions | Выделение с копированием при отпускании мыши, /copy |
| Поиск слов | Доступен в upstream интерфейсах | Исключён по решению пользователя |
| История через Esc | Поведение upstream различается | Esc возвращает последние сообщения, затем родителя дочернего чата |
| Фокус и режим | Сочетания upstream различаются | Tab меняет фокус, /basic и /plan выбирают режим |

- [x] UX: убрать из интерфейса подсказки `PgUp`/`PgDn`, `Ctrl+F` и `↑`/`↓`.
  Удалить сам бинд `Ctrl+F`; навигацию клавишами истории и существующее
  поведение `Esc` сохранить.

- [ ] Сводки plan-сессий: проверять через canonical reducer с доверенным
  каталогом read-only инструментов. До этого статус сводки «Недоступна».
- [ ] Баш-совместимый возврат к файлам после редактирования shell-строки:
  zsh использует ZLE hooks; для bash нужна столь же надёжная граница приглашения.
