# Что останавливает работу ANSA

Аудит обычного Work, прямого делегирования и запуска утверждённого плана. Исходная версия - `d5bf4ed`. Проверены пути допуска и выполнения в Rust, журнал, восстановление и интерфейс Carbon. Работа внешних MCP-серверов и качество ответов живой модели требуют отдельных проверок.

## Причины остановок

| Где | Что происходило | Решение |
| --- | --- | --- |
| Прямое поручение при открытом shell | Терминал ведущего удерживал право записи для каталога. Файловый инструмент помощника пытался занять тот же каталог как другая сессия. Даже правка одного разрешённого файла возвращала `terminal_workspace_busy`. | Ведущий передаёт прямому исполнителю доступ к своей блокировке на время поручения. Каждая правка по-прежнему проверяет путь, владельца и отмену. |
| Обычный Work и помощники | Если искомый текст перестал совпадать с файлом, известный отказ завершал весь ход. | Модель получает причину и `applied:false`. Она может перечитать файл и составить новое изменение. Вызов автоматически не повторяется. |
| Крупные исходники | Полный текст до и после правки должен был поместиться в квитанцию. Даже замена одной строки в файле крупнее 64 КиБ была невозможна. | Новый `edit_file` поддерживает файлы до 1 МиБ. Для крупного файла сохраняются точный изменённый фрагмент, позиция и хэши файла. Старые журналы сохраняют свой контракт инструмента. |
| Чтение соседнего теста | Чтобы помощник мог прочитать тест, ведущий включал его в список разрешённых правок. | В новом поручении `paths` задаёт область записи, `read_paths` добавляет файлы только для чтения. Уже принятые поручения сохраняют исходные разрешения. |

В **Work и прямом Orchestrate** число вызовов за ход по умолчанию не ограничено. В проверенной сессии три помощника сделали по пять отдельных вызовов `edit_file`. Это были решения моделей внутри трёх поручений. В **`/propose+`** действует отдельный процесс с исполнителем, проверяющим и возможной эскалацией. Подтверждённый проверяющим блокер завершает шаг. [Прямое поручение](../rust/crates/ansa/src/frontend/sessions/delegate.rs) · [Исполнение утверждённого плана](../rust/crates/ansa/src/frontend/orchestration/plus.rs)

## Где runtime должен принимать решение

| Граница | Что проверяет ANSA | Почему это важно |
| --- | --- | --- |
| Инструменты | Весь пакет получен и проверен перед первым вызовом. Отмена прекращает новый запуск. Известные результаты и неопределённые эффекты записываются раздельно. | После обрыва нельзя второй раз запустить уже выполненную команду. [Допуск](../rust/crates/ansa/src/tools/admission.rs) · [Runtime](../rust/crates/ansa/src/runtime/work.rs) |
| Файлы помощника | Исполнитель может читать оба списка путей и редактировать только `paths`. Два пустых списка разрешают исследовать проект. Терминал остаётся у ведущего. | Расширение контекста для чтения не даёт права записи. После восстановления журнал определяет ту же область доступа. [Поручение](../rust/crates/ansa/src/tools/delegation.rs) · [Область файлов](../rust/crates/ansa/src/tools/files.rs) |
| Команды кандидата | При утверждении показан точный argv. Команда выполняется в копии кандидата с правами пользователя. | Копия изолирует входное дерево для проверки. Запущенный процесс по-прежнему имеет доступ к разрешённым пользователю файлам и сети. Область файлов помощника на процесс не распространяется. [Запуск проверок](../rust/crates/ansa/src/frontend/orchestration.rs) · [Процесс](../rust/crates/ansa/src/process/runner.rs) |
| MCP и skills | Доступность инструмента MCP в Plan зависит от локального списка `read_only`. Файл навыка добавляет инструкции в контекст. | Поведение MCP определяют сервер и его учётные данные. Для строгого чтения нужны соответствующие права на самом сервисе. Локальный stdio-сервер запускается при сборке каталога. Текст навыка не меняет выданных агенту прав. [MCP](../rust/crates/ansa/src/mcp.rs) · [Профили навыков](HARNESS_PROFILES.md) |

## Оставшиеся ограничения

- **Ведущий ждёт помощника.** Прямой `delegate_task` завершается вместе с дочерним ходом. Пока он выполняется, можно задать вопрос в чате. Ветка ответа не получает свежие квитанции дочерних инструментов. Для независимых фоновых задач нужны отдельные запуск, доставка результата и восстановление по ID. [Делегирование](../rust/crates/ansa/src/frontend/sessions/delegate.rs) · [Состояние хода](../rust/crates/ansa/src/session/state.rs)
- **Утверждённые планы.** В исходной версии `Start` у плана на реализацию требует командную проверку. Журнал запуска отдельно ограничивает число отправок и возобновлений. Эти условия относятся к явным `/propose` и `/propose+`. В воспроизведённом отказе прямого помощника эти ветви не исполнялись. [План](../rust/crates/ansa/src/orchestration/plan.rs) · [Запуск](../rust/crates/ansa/src/frontend/orchestration.rs)

- **Бюджет, явно заданный оператором.** Отклонённая группа вызовов расходует позиции в сегменте. При `tool_calls:1` может понадобиться `/retry` до первой выполненной операции. При изменении учёта нужно сохранить идентификаторы отклонённых вызовов для replay. [Состояние сессии](../rust/crates/ansa/src/session/state.rs)
- **Хранилище утверждённых запусков.** Журнал оркестрации принимает до 240 записей. При открытии они загружаются в память. Для существенно более длинных запусков нужна постраничная загрузка или смена сегмента. У обычного чата другой журнал. [Журнал оркестрации](../rust/crates/ansa/src/orchestration/journal.rs)
- **Вложения и вывод.** В одном сообщении помещаются до четырёх изображений и суммарно до 2 МиБ отправляемых изображений. Большое чтение файла возвращает страницы по 8 КиБ. Вывод `run_command` можно дочитать через `read_output` в пределах сохранённых 256 КиБ на поток. Эти величины ограничивают объём отдельных данных. [Изображения](../rust/crates/ansa/src/provider/contracts/image.rs) · [Вывод процесса](../rust/crates/ansa/src/process/output_spool.rs)
