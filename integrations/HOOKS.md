# P1 Hooks: наблюдение за ANSA через JSONL

`ansa_hooks.py` — отдельный opt-in адаптер для Linux и Python 3.8+ (стандартная библиотека с SQLite ≥ 3.24). Он читает ANSA v1 JSONL со stdin и отправляет по одной JSON-датаграмме в явно указанный Unix-сокет для каждого события подписки. Получатель может вести счётчики, писать свой журнал или показывать уведомления. ANSA не запускает адаптер и не читает настройки hooks из проекта. Hooks не управляют ходом, не блокируют допуск инструментов и не заменяют политику удаления файлов.

## Подключение

Создайте каталог вне рабочего проекта с правами `0700`, принадлежащий пользователю адаптера. В примерах ниже `hook_dir` — его абсолютный путь; путь к сокету должен занимать не более 107 байт. Сам каталог и файл состояния сохраняйте между перезапусками. Используйте отдельный файл состояния для каждого независимого журнала: разные процессы `--live-jsonl` могут иметь одинаковое wire-значение `session=live`. Запустите отдельно собственный доверенный получатель. Для проверки можно использовать этот приёмник, который печатает только полученные метаданные:

```sh
python3 -B - "$hook_dir/events.sock" <<'PY'
import socket
import sys

with socket.socket(socket.AF_UNIX, socket.SOCK_DGRAM) as listener:
    listener.bind(sys.argv[1])
    while True:
        print(listener.recv(512).decode("ascii"), flush=True)
PY
```

Сокет должен быть привязан до запуска наблюдателя. При перезапуске получателя удалите оставшийся файл сокета *после* остановки прежнего получателя; файл SQLite не удаляйте.

Направьте stdout `ansa --live-jsonl --session /absolute/path/to/journal` или `ansa --offline-jsonl` в адаптер. Для работы с ходами ваш JSONL-клиент по-прежнему читает исходный поток ANSA и пишет команды в stdin ANSA (например, `submit` с `session` и `incarnation` из стартового `snapshot`). Передайте адаптеру отдельную копию stdout, без stderr и входящих команд. Например, в Bash с GNU `tee -p` (переменные — пути, выбранные оператором):

```sh
ansa --live-jsonl --session "$journal" < "$commands_fifo" |
  tee -p >(python3 -B "$checkout/integrations/ansa_hooks.py" \
    --state "$hook_dir/cursor.sqlite" --socket "$hook_dir/events.sock" \
    --subscribe session_opened --subscribe command_accepted --subscribe done \
    --subscribe cancelled --subscribe tool_started --subscribe tool_finished) \
  > "$events_fifo"
```

Здесь `commands_fifo` и `events_fifo` — заранее подключённые каналы вашего клиента. `tee -p` продолжит обслуживать клиента, если наблюдатель закроет pipe, но медленная ветка всё ещё может задержать `tee`. Если задержка основного клиента недопустима, делайте в клиенте отдельную ограниченную очередь для копии потока и допускайте потерю событий наблюдения при перегрузке. Адаптеру нужны только stdout JSONL, свой SQLite и сокет. Он не читает журнал ANSA или auth store. Обычный текстовый вывод Carbon не является этим потоком.

## Файл состояния

- `--state` — абсолютный путь без symlink в любом компоненте и без `.` или `..`. Непосредственный каталог должен принадлежать эффективному UID адаптера и иметь режим `0700`. Вышестоящие каталоги должны принадлежать этому UID или root; запись для группы или остальных допустима только со sticky bit (например, `/tmp`). Не меняйте путь, права и содержимое каталога, пока адаптер работает; процессы с тем же UID и root считаются доверенными.
- При первом запуске укажите ещё не существующий файл. Адаптер создаст его с режимом `0600`. Уже существующий файл должен быть обычным файлом того же владельца, с правами `0600` и ровно одной жёсткой ссылкой. До открытия на запись проверяются формат SQLite (без WAL), маркер `ANSH`, точная схема адаптера, ключ и лимит размера. Совместимое состояние от предыдущей версии сохраняет ключ и курсоры; пустой файл или посторонняя SQLite-база не инициализируются.
- Имена с суффиксами `-journal`, `-wal` и `-shm` зарезервированы. Если рядом с выбранным файлом уже есть любой такой sidecar, адаптер завершится с `state_unavailable`, не открывая и не удаляя его. Это относится и к журналу активной транзакции или журналу, оставшемуся после сбоя. Если другой экземпляр ещё работает, дождитесь его окончания. После сбоя сохраните базу вместе с журналом для диагностики и восстановления; не удаляйте журнал и не сбрасывайте курсоры ради запуска.

## События и формат

| `--subscribe` | Источник v1 |
| --- | --- |
| `session_opened` | Стартовый `snapshot` (`stream_sequence=through_sequence=1`, без ID запрошенного снимка). Открытие экземпляра runtime, в том числе при восстановлении сессии. |
| `command_accepted` | Новый принятый `submit` или `resume`. Запуск наблюдения за ходом не означает успешного завершения. |
| `done`, `cancelled` | Соответствующее событие runtime. Отмена не откатывает эффекты инструментов. |
| `tool_started`, `tool_finished` | Соответствующее событие runtime; связываются по `operation_id`. |

Базовые поля: `hook_version` (целое `1`), `event`, `stream_id`, `session_id`, исходный `stream_sequence`. События хода и инструментов добавляют `turn_id`, события инструментов — `operation_id`. Только `tool_finished` содержит `execution` (`succeeded`, `failed`, `cancelled`, `denied`) и `effects` (`not_started`, `known_result`, `effect_unknown`). Все строковые идентификаторы в датаграмме — HMAC-псевдонимы, стабильные для одного файла состояния. `stream_id` различает runtime incarnation; `turn_id` также учитывает request ID. Ключ псевдонимов хранится только в приватном SQLite. Содержимое сообщения, аргументы, результаты, имена инструментов, исходные ID, пути и диагностика не передаются. Приёмник всё равно видит факт, порядок и время активности. Не подключайте вход адаптера к недоверенному источнику: v1 не удостоверяет, что кадр пришёл из runtime.

## Пропуски, replay и ограничения

- Одно упорядоченное чтение на каждый исходный поток. `command_replayed`, preview, история и содержимое snapshot не порождают уведомлений. При `resync_required` адаптер показывает `stream_gap`; он не запрашивает пропущенные события и не синтезирует их из снимка.
- Для каждого `stream_id` SQLite запоминает наибольший sequence событий из таблицы выше (в том числе неподписанных) и `resync_required`. Адаптер коммитит курсор **до** попытки отправки; повторы и более старые кадры пропускаются, в том числе после перезапуска с тем же `--state`. Смена подписки не отправляет историю. Новый `incarnation` — новый поток. Не подавайте архивы в новую базу: ранее не встречавшийся кадр архива неотличим от живого события. Не откатывайте состояние к старой копии, если нужно сохранить защиту от дублей.
- Это доставка *не более одной попытки*, без подтверждения и без повторов. Отсутствующий или занятый получатель, переполнение потока либо остановка после коммита курсора могут привести к потере уведомления. Отправка ограничена 100 мс, ожидание блокировки SQLite — 250 мс. База растёт на одну строку за incarnation; при достижении лимита (4096 страниц) адаптер прекращает доставку вместо удаления старых курсоров. Используйте локальную файловую систему.
- Один входной кадр ограничен 16 МиБ плюс LF; хвост длинного кадра отбрасывается порциями. Повреждённые кадры и ошибки доставки не останавливают чтение. Диагностика идёт в stderr короткими кодами (не более одного сообщения на код); при ошибке адаптер возвращает `1`, а при ошибке состояния останавливается сразу. В stdout адаптер ничего не пишет.

