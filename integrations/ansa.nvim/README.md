# ansa.nvim

Neovim рядом с Carbon: история разговора, выделение для агента, отчёты,
графики и просмотр предложенных правок.

Соберите программу через `nix build --no-update-lock-file`. Запустите Carbon:

```sh
./result/bin/ansa --workspace-dir /run/user/$(id -u)/ansa-workspace --workspace-editor
```

В соседнем split Kitty или Ghostty:

```sh
./result/bin/ansa-nvim --socket /run/user/$(id -u)/ansa-workspace/workspace.sock --editor
```

Аргументы и файлы Neovim передаются после `--`, например `-- src/main.rs`.
Пакет содержит Neovim 0.12.5, Markdown parsers, `render-markdown.nvim`,
`snacks.image` и ImageMagick. Launcher открывает подготовленную конфигурацию
ansa; фон берётся из терминала.

Для подключения в своей конфигурации добавьте интеграцию в runtimepath:

```lua
vim.opt.runtimepath:prepend('/path/to/ansa/integrations/ansa.nvim')
require('ansa').setup()
```

```vim
:AnsaAttach /run/user/1000/ansa-workspace/workspace.sock
:AnsaHistory
```

Используйте свой UID и путь. Каталог endpoint должен принадлежать пользователю
и иметь права `0700`; socket создаётся с `0600`. Занятый socket не удаляется
автоматически. Endpoint привязан к исходному разговору Carbon.

`:AnsaRefresh` явно обновляет историю, `:AnsaDetach` отключает viewer.
Отключение сохраняет открытый документ и не отменяет работу агента. Обновления
сохраняют положение чтения; если буфер изменён, новая версия доступна отдельно.
Plugin не записывает файл и не повторяет задачи при reconnect.

Базовый клиент требует Neovim с `vim.uv`, `vim.json` и `nvim_exec2` (0.10+).
Renderer проверен в закреплённом пакете 0.12.5.

Для явной передачи выбранных строк запустите owner с `--workspace-editor`,
подключитесь через `:AnsaAttach! PATH` и выполните `:AnsaShare` с диапазоном.
Несохранённый текст доступен через `workspace_describe` и `editor_get_context`.
Изменение или закрытие буфера отзывает переданную версию.

`:AnsaSend вопрос` отправляет выбранные строки вместе с вопросом. Если агент
занят, сообщение уточняет его текущую задачу. Режим берётся из Carbon; команда
не сохраняет исходный файл. `:AnsaShare` предоставляет контекст без отправки задачи.

`:AnsaPending` проверяет исход отправки по прежнему ID. При потере соединения
плагин сохраняет сообщение и после reconnect повторяет только проверку статуса.
Если отправку подтвердить не удалось, проверьте историю; `:AnsaForgetPending!`
снимает локальную блокировку следующей отправки. `:AnsaCancel` останавливает свою
подтверждённую задачу. Неизвестный исход автоматически не повторяется.

## Отчёты и предложенные правки

| Команда | Действие |
|---|---|
| `:AnsaArtifacts` | Выбрать сохранённый Markdown, CSV или PNG |
| `:AnsaArtifactsEarlier` | Загрузить предыдущую страницу результатов |
| `:AnsaArtifact ID REVISION` | Открыть определённую версию артефакта |
| `:AnsaDocuments` | Выбрать подготовленный файл или proposed diff |
| `:AnsaDocumentsEarlier` | Загрузить предыдущую страницу документов |

Выбранная старая версия остаётся открытой при обновлении списка результатов.
Новая версия изменённого пользователем отчёта открывается отдельно. Задержанный
ответ не переключает окно, если за время чтения пользователь продолжил печатать
или прокручивать документ. Повторный показ читает сохранённые файлы и не запускает
анализ заново.

Агент может проверить CSV через `dataset_inspect` и построить помесячные суммы
через `python_execute`. Например:

```text
Посчитай помесячные суммы в sales.csv: дата в date, сумма в amount.
Используй report_key sales. Подготовь таблицу и график.
```

Формат даты - `YYYY-MM-DD`. Числа содержат до 18 целых и 6 дробных цифр;
итоги считаются точно. Результат включает Markdown, CSV и PNG.
Исходный CSV ограничен 4 MiB, один анализ - 60 секундами,
хранилище результатов сессии - 64 MiB. Ранние версии сохраняются.
Подробные пределы - в [WORKSPACE_PROTOCOL](../../docs/WORKSPACE_PROTOCOL.md).

Графики показываются в отдельном буфере. Enter разворачивает график из split
Neovim на всю ширину редактора. Повторный Enter возвращает к split. В одиночном
окне Enter открывает PNG в системном просмотрщике. Клавиша `o` открывает его
из любого графического буфера. Проверенная связка - Kitty 0.49.2
и Ghostty 1.3.1 на Linux/aarch64 с Neovim 0.12.5. Поддержка PNG проверяется
ответом терминала. При `NO_COLOR`, SSH, tmux или неподдержанной графике остаются
описание и путь к сохранённому файлу. PNG через эти transports требует
отдельной проверки.

`editor_open_file` подготавливает просмотр исходника, `editor_propose_diff` -
сравнение переданного выделения с предложением агента. `:AnsaDocuments`
открывает предложение в обычном Neovim diff. Принятие правки выполняется
пользователем в редакторе; исходный файл и несохранённый буфер сохраняются.

## Панель Kitty

Для открытия соседней панели из текущей вкладки Kitty:

```sh
./result/bin/ansa-nvim --kitty --socket /run/user/$(id -u)/ansa-workspace/workspace.sock --editor
```

Нужны layout `splits` и локальный remote-control socket. Launcher берёт
`KITTY_LISTEN_ON` и `KITTY_WINDOW_ID`; их можно задать явно через
`--kitty-to unix:/путь` и `--parent ID`. Socket должен принадлежать пользователю
и иметь права `0600` либо находиться в private каталоге `0700`.
Kitty должен заранее разрешать этому socket команды `ls` и `launch`.

Повторный вызов находит ту же панель по собственному ID. При потере подтверждения
проверяется прежний запуск. `--reopen` открывает подтверждённо закрытую панель;
неизвестный исход требует проверки. Состояние панели хранится в `kitty-viewers/`
рядом с workspace socket. Для Ghostty/Linux используется созданный вручную split.
